# 구조

작성일 2026-11-05, 기준 `7a647af`. 모드 이름 `pixel-tavern`, 명령 `/tavern`·`/tavern-diag`.

## 한 줄 설명

Claude Code 데스크톱의 "모드"(hooks 모듈)로, 프롬프트 위의 픽셀 배너(`AbovePrompt`)와 오른쪽 패널(`Pane`, 이름 "여관")을 그린다. 상태는 `$.state`(세션)·`$.store`(세션 너머), 바깥 세계는 `$.process`로 만난다.

## 의존 방향

```
register ─┬─ actions ── radio ── state ── git
          ├─ alerts                  └─ scenes · format · volume
          ├─ banner ── usage · svg · scenes · format · still
          └─ panel ─── layout · music · gitrows · quick · usage · diag · theme · still …
```

- 화면 파일은 상태를 직접 읽지 않고 `PanelData`/`BannerData`로 값을 받는다. 렌더 훅은 읽기만 한다(값을 쓰는 곳은 `actions`·`register`).
- 실행 시점 순환은 없다. `layout`·`music` → `panel`(`PanelData`), `panel` → `banner`(`BannerData`)는 타입만 가리킨다.
- 바깥 세계(git, 재생기 프로세스)는 각각 한 파일에 갇혀 있다.
- 엔진의 검사와 타입 검사에서 알게 된 규칙: (1) `$`를 받는 함수는 파일 맨 위에 선언한다(`register` 같은 함수 안에 두면 모드가 불러와지지 않는다). (2) atom은 읽고 쓰는 파일 안에 선언한다. (3) 같은 일을 하는 훅을 도구 이름 여럿을 도는 반복문 하나로 쓰지 않고 도구마다 하나씩 쓴다(타입 검사기가 합집합 입력 모양을 계산하다 메모리가 바닥난다). (4) `$.ui.open`의 인자는 엔진 타입이 말하는 것만 쓴다(`backgroundColor`는 없다).

## 데이터 흐름

이벤트(세션 시작·60초마다·턴 끝·도구 호출·버튼) → `register`/`actions`가 상태(atom)와 저장소를 갱신 → 상태를 읽는 `ui.render` 훅이 다시 그림.

- 60초마다 갱신하고(`refresh`), 턴이 끝나면 git을 바로 다시 읽는다(배너의 +N이 맞도록).
- `Edit/Write/NotebookEdit` 호출이 성공하면 `trackFile`이 파일을 기록한다(이 채팅 목록 50개는 경로로, 오늘 통계는 경로 대신 지문으로 500개). 이때 제어 문자를 뺀다.
- 오늘 통계(`stats.ts`)는 채팅마다 **자기 칸**(`today:<날짜>:<칸 이름>`)에만 누적값을 쓴다. 저장소에는 원자적 갱신이 없어서 모두가 한 키를 읽고-고치고-쓰면 같은 순간에 늘린 것이 사라진다(시험으로 재현: 10에서 둘이 늘려 11). 합계는 읽는 쪽이 모든 칸을 더해 만들고(1분마다와 시작할 때), 내 칸은 한 줄로 세워 쓰며 1분마다 다시 써서 사라진 쓰기를 바로잡는다. 지난 날의 칸과 옛 합계 키(`today`, 읽기 전용으로 호환)는 정리한다. 칸 이름은 `$.state`에 남아 모드를 다시 불러와도 같고, 앱을 다시 켜면 새로 정한다(앞 칸은 합계에 남는다).
- 할 일 목록(`todos.ts`): 항목(`id`·글자·완료·우선) 목록을 저장소의 `todos` 한 키에 둔다(모든 채팅이 같은 목록을 쓴다). 바꿀 때마다 저장소의 **최신 목록을 읽고 그 위에 바꿔** 저장하고(다른 채팅이 그동안 더한 일을 덮어쓰지 않는다) 화면의 값(`todos` 상태)도 같은 값으로 바꾼다. 같은 채팅의 바꾸기는 약속을 이어 붙인 한 줄로 세우며, 읽을 때는 모양이 틀린 항목·같은 id·빈 글자를 버리고 50개까지만 남긴다. 1분마다(`refresh`) 저장소를 다시 읽어 다른 채팅의 변경이 보인다. 새 일은 맨 앞에 쌓이고 화면에서는 우선인 안 한 일 → 안 한 일 → 완료한 일 순서로 보인다(`orderTodos`). `$`를 받는 함수는 `const` 화살표 함수가 아니라 함수 선언이어야 한다(엔진의 검사).
- 프로젝트별 오늘(`byProject`): 칸의 값에 이 채팅의 프로젝트 폴더 이름(`project`, 경로가 아니라 이름만. 제어 문자를 빼고 40글자까지)이 더해진다. 이름은 세션이 시작할 때 `writeProject`가 정하고, 날이 바뀌어 칸이 새로 시작해도 이어진다. 합계를 만들 때 다른 칸들을 이름별로 묶어(숫자는 합, 파일 지문은 합집합) 상태(`projects`)에 두고, 화면에서는 이 채팅의 칸과 다시 묶어 많이 한 순서로 10개까지 보인다. 묶어 두는 단계에서는 자르지 않는다(잘린 프로젝트를 이 채팅이 이어 하면 숫자가 모자라서). 이름이 없는 칸(이 기능 전의 기록, 옛 합계 키)은 빈 이름 하나로 묶여 `이전 기록`으로 보인다. 오늘 두 프로젝트 이상일 때만 `projects.tsx`가 접이식 줄을 그린다(기본 접힘).
- 방송 고르기(`stations.ts`): 장면마다 기본 방송(`scenes.ts`)이 있고, 패널 음악 구역의 묶음 버튼(★ 즐겨찾기 · 잔잔 · 7080 · 게임 · 신스)과 그 묶음의 방송 버튼으로 다른 방송을 고르면 장면별로 기억한다(`stationChoices`). 목록을 스크롤하는 선택 칸(`Select`)은 쓰지 않는다. 즐겨찾기(`favoriteStations`)는 방송 단위이고 ★ 묶음에 모이며 방송 버튼 이름 앞에 `★`가 붙는다. 보고 있는 묶음(`stationTab`)은 저장하지 않는 보기 상태이고(비어 있으면 지금 방송의 묶음), 장면을 바꾸면 비워진다. 장면은 `moveScene`(◀ ▶, 배너 ⟳와 같은 순서)으로 넘긴다. 배너와 패널은 장면의 `music`을 그대로 읽으므로 `readView`가 고른 방송으로 바꿔 끼운 장면을 돌려주고(그림·색은 그대로), 재생기(`startRadio`)는 켤 때 `readStation`으로 고른 방송의 주소를 받는다. 방송을 바꾸면 켜져 있을 때만 새 방송으로 다시 켜고(음량 바꿀 때와 같다), 꺼져 있으면 켜지 않는다. 즐겨찾기·선택은 값을 읽고 따로 쓰지 않고 바꾸는 순간의 값에서 바꿔 저장한다. 저장하는 것은 방송 이름표(id)뿐이며, 읽을 때 모양이 틀린 값·모르는 장면·모르는 방송은 버린다. 방송 주소는 모두 `http`이고 접속하는 서버는 사용자가 승인한 8곳뿐이다(시험이 서버 이름을 허용 목록과 대조).
- 두 채팅이 저장소(`$.store`)를 실시간으로 공유하는 것을 앱에서 확인했다(음악 소유권 표시 "다른 채팅에서 재생 중"이 서로 바뀜) **[사람 확인]**.
- 움직임 끄기(`still.ts`): 그림의 움직임은 모두 "요소 바로 안의 `<animate…/>` 하나"라는 같은 모양이라(생성 도구의 깜박임·프레임·이동과 장면별 불빛, 4장면 모두 시험으로 확인), `isStill`이 참이면 그 첫 값을 부모 요소의 속성으로 굳히고 `<animate>`를 지운다(깜박임은 켜진 모양, 프레임은 첫 프레임만 보임, 이동은 처음 자리). 그림 파일과 생성 도구는 그대로이고 그림을 두 벌 만들지 않는다. 배너 띠는 글자를 얹기 전에, 패널 그림은 게이지를 끼워 넣은 뒤에 바꾼다(게이지 그림에도 움직임이 있어서). 바꾸는 데 걸리는 시간이 0.06~2.8ms(Node에서 잰 값, 앱에서는 [미검증])라 캐시는 두지 않는다. 설정은 `$.store`의 `isStill`에 저장하고(모양이 틀린 값은 버림) 이 채팅의 상태에는 `isStill` 값으로 둔다. 버튼은 바꾸는 순간의 값에서 뒤집어 거의 동시에 두 번 눌러도 한 번이 사라지지 않는다. 다른 채팅에는 앱을 다시 불러와야 반영된다(장면·숨김과 같음).
- git 정보(`git`)는 상태 값에 shape 태그(`git-1`)를 붙였다. 모양이 바뀌면(바뀐 파일 목록이 생긴 것처럼) 모드를 다시 불러올 때 옛 값을 읽지 않는다.
- 빠른 실행 버튼(`work.ts`)은 누르면 "대기", 그 뒤 처음 시작하는 메인 대화 턴(`turn.start`)에 붙어 "진행 중", `turn.complete`에서 "끝·중단·실패"가 된다(끝은 60초 뒤 사라짐, 이 상태는 저장하지 않는다). 서브에이전트의 턴은 건너뛰고, 모델의 답·프롬프트 글은 읽지 않는다. `$.command.run`의 호출이 끝났다는 것은 작업이 끝났다는 뜻이 아니라서(프롬프트를 보내는 명령은 호출 뒤에 작업이 돈다) 완료 신호로 쓰지 않는다. 눌림마다 번호를 붙여, 세션이 바빠 줄 서 있던 옛 눌림의 호출이 끝나도 새 눌림의 표시를 건드리지 않는다.

## 재생기 수명

상태: `off → connecting → playing`, 그리고 `failed`(켜지 못함·스스로 끝남·연결 포기), `other`(다른 채팅이 가져감).

끝나는 길은 세 가지다.

1. ■ 또는 장면 바꿈: `listen`의 반복문을 `break`로 나오면 엔진이 자식 프로세스를 끈다.
2. 모드 다시 불러오기: 엔진이 자식을 함께 끈다(엔진 규칙, 미검증).
3. 앱 강제 종료: 재생기가 5초마다 부모 프로세스가 살아 있는지 보고 없으면 스스로 끝난다 [실측 4초 이내, 실제 앱에서도 사용자가 확인].

소리가 안 흐르면 점점 길게 기다리며(15초·30초·60초·2분·2분) 다시 연결하고(다시 연결할 때마다 `connecting` 다음에 `retry:번호`를 알려 패널에 "다시 연결하는 중(2/5)"을 보임), 5번 실패하면 `gaveup`을 알리고 끝낸다(약 6분). 한 번이라도 재생되면 횟수를 다시 센다. 다른 채팅의 재생기는 명령줄에 표식과 실행 인자 서명이 둘 다 있는 것만 먼저 끈다.

## 저장하는 것(`$.store`)

`mood`(장면), `isHidden`(배너 숨김), `isStill`(움직임 끄기), `stationChoices`(장면별로 고른 방송), `favoriteStations`(즐겨찾기한 방송), `todos`(할 일 목록), `today:<날짜>:<칸>`(채팅별 오늘 통계 칸), `volume`, `collapsed`(접은 구역), `introSeen`(첫 안내), `radioOwner`(음악을 켠 채팅의 이름표). 오늘 통계 칸에는 숫자와 수정한 파일의 **지문(경로의 8자리 해시)**, 그리고 **프로젝트 폴더 이름**(경로 아님)만 들어가고 경로는 저장하지 않는다. 타임라인·프로젝트별 통계를 만들 때도 무엇을 저장할지 이 기준으로 정한다.
