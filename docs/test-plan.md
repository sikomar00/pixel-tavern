작성일 2026-11-05. 시험은 세 겹입니다: **자동 시험**(가짜 엔진) → **실제 Windows 점검**(재생기, 소리 없음) → **사람 확인**(실제 앱).

**자동 시험이 보장하는 것**: 화면에 나오는 글자·버튼·그림의 값, 상태가 바뀌는 순서, 호출하는 명령과 인자, 오류가 났을 때의 표시.
**보장하지 못하는 것**: 실제 앱에서 그려진 모습(색·간격·잘림), 마우스 올림 설명, 실제 저장소 공유·유지, 실제 프로세스 수명, 실제 소리. 재생기 스크립트는 시험에서 "글자가 들어 있는지"만 확인한다(R-17).

## 2. 실제 Windows 점검 — `tools/player_check.py`

재생기(PowerShell + MediaPlayer)를 **음량 0**으로 실제로 돌립니다. 표준 라이브러리만 씁니다.

| 명령 | 시간 | 기대 결과 |
|---|---|---|
| `python tools/player_check.py normal` | 약 30초 | `playing`까지 약 5초, 메모리 약 140 MB, 끈 뒤 0개 |
| `python tools/player_check.py dead` | 약 100초 | 연결 시도 5번, 약 79초에 `gaveup`, 종료 코드 0 |
| `python tools/player_check.py orphan` | 약 40초 | 부모를 강제로 죽인 뒤 5~10초 안에 재생기 0개 |

**주의**: 재생기는 시작할 때 이미 켜져 있던 다른 재생기를 끕니다(설계: 소리는 한 곳에서만). 이 점검을 돌리면 지금 듣고 있는 음악도 꺼집니다. 인터넷 연결이 필요합니다(`normal`).
**언제 돌리나**: `hooks/radio.ts`의 `PLAYER`를 고칠 때마다 세 가지를 모두.
