## 2026-11-05 Git 파일 이름을 -z 로 읽기 — F-10(커밋 `194cd7e`~`e6f3205`, 푸시 완료)

- **fix(git)**: `git status`를 줄 단위가 아니라 `--porcelain=v1 -z -b`(NUL 구분)로 읽음. 실제 git 출력으로 재현한 결함: 이름 변경의 새 이름에 ` -> `가 들어 있으면 이름이 잘리고(`renamed -> to new -> name.txt` → `name.txt"`), 따옴표·탭·줄바꿈이 든 이름은 `\"`, `\t`, `\n` 이스케이프 글자가 그대로 보였다. `-z`는 이름을 있는 그대로 주고 이름 변경은 "XY 새 경로" 다음 칸에 옛 경로를 따로 주며(건너뜀), 충돌 코드(UU·UA·AU·DD)는 경로가 하나뿐이라 이름 변경보다 먼저 판단한다. 출력이 4MiB에서 잘리면 조각난 마지막 항목은 버린다. `-z`가 대신하므로 `core.quotePath=false`는 뺐다.
- **test**: `tests/git.test.tsx` 12개(기존 10개 중 옛 줄 단위 형식을 단언하던 2개를 `-z` 형식 시험으로 교체, 새 시험 4개 추가). **실제 git `-z` 출력 고정 자료**(22칸)로 검증: 이름 변경의 양쪽 이름에 ` -> `, 따옴표, 탭, 줄바꿈, 이모지, 악센트+공백, 이름 변경+수정(RM), 이름 변경끼리의 충돌(UA·AU·DD), 합치기 충돌, 새 폴더. `kit`에 줄 단위 자료를 `-z` 모양으로 바꿔 주는 `toPorcelainZ`와 `isZ`·`isTruncated` 옵션 추가(기존 패널 시험의 자료는 그대로). 기존 시험 변경: `data.test`의 `parseStatus` 입력 2곳을 변환기를 거치게, `safety.test`의 git 인자 확인을 `-z` 포함 확인으로 바꿈. 변이 확인: 옛 파서로 되돌리면 12개 중 10개, 옛 경로 칸 건너뛰기·잘림 처리를 각각 없애면 해당 시험이 실패(격리 환경).
- **chore(tools)**: `tools/git_fixture.py` 추가 — 실제 git으로 어려운 이름이 든 임시 저장소를 만들어 `status -z` 출력을 찍는다(고정 자료와 글자까지 같음). Windows는 이런 이름을 만들 수 없어 인덱스에 직접 넣는다(`core.protectNTFS`를 임시 저장소에서만 끔).
- **docs**: F-10, R-23(실제 앱의 NUL 전달 미검증), R-24(역슬래시 이름 미검증) 추가, 구조·보안·기능 매트릭스·시험 계획·계획 갱신.
