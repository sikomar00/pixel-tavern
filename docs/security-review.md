기준: 커밋 `271ff83` + 커밋 전 수정. 작성일 2026-11-05. 코드를 읽고 검색해서 확인했고, 재생기는 실제 Windows에서 소리 없이 돌려 보았습니다.
**[확인]** 코드·실행으로 확인 · **[시험]** 자동 시험 · **[미검증]** 확인하지 못함

## 1. 바깥에서 들어오는 입력은 매우 적다

이 모드는 서버가 아니고 사용자 입력 칸도 없습니다. 값이 들어오는 곳은 아래 네 곳뿐입니다.

| 입력 | 어디서 오나 | 어디로 가나 | 평가 |
|---|---|---|---|
| 방송 주소 | `scenes.ts`의 상수 4개 | 재생기의 환경변수 `TAVERN_URL` | 사용자·모델이 바꿀 수 없음 |
| 음량 | 버튼 5단계 → 고정 표(`volume.ts`) | 환경변수 `TAVERN_VOLUME` | 숫자 값이 고정 |
| 슬래시 명령 | `QUICK` 상수(`/code-review`, `/commit-commands:commit`, `/simplify`) | `$.command.run` | 고정 |
| **파일 경로** | 모델의 `Edit/Write/NotebookEdit` 호출 인자(`file_path`) | 패널 버튼 이름, 클릭하면 프롬프트에 `@경로` 채움 | **제어 문자 문제를 찾아 고침(F-04)** |
| git 출력 | 사용자 폴더의 `git status/log` | 패널에 글자로 표시 | 글자로만 쓰임 |

## 2. 점검 항목별 결과

**명령 주입 [확인]** 모든 외부 프로세스는 인자 배열로 실행해서 셸이 해석하지 않습니다(`process.run/spawn`). PowerShell 재생기는 `-Command`로 상수 스크립트를 받고, 바뀌는 값(주소·음량)은 환경변수로 넘기므로 스크립트에 값이 끼어들지 않습니다.

**입력 검증 [확인]** 검증이 필요한 경계는 파일 경로 하나였습니다. 줄바꿈 등 제어 문자(`\u0000-\u001f`, `\u007f`)를 기록 시점에 한 곳(`trackFile`)에서 뺍니다. 이 문자가 남으면 (a) 엔진이 버튼을 거부해 패널 전체가 사라지고 (b) 프롬프트 칸에 여러 줄이 끼어들 수 있었습니다. [시험] `tests/safety.test.tsx` — 고치기 전에 (a)가 실제로 재현됨.

**경로 검증 [확인]** 모드는 파일을 읽거나 열지 않습니다. 경로는 글자로 저장·표시하고 `@경로` 텍스트를 프롬프트에 채울 뿐이라, 경로 이탈(`..`)로 얻는 접근이 없습니다. 실제로 파일을 읽는 것은 사용자가 보낸 뒤의 엔진입니다.

**프로세스 인자·수명 [확인]**
- PowerShell은 `-NoProfile -NonInteractive -WindowStyle Hidden`으로 띄워 사용자 프로필 스크립트를 실행하지 않습니다.
- 수명: `■`(반복문을 나오면 자식 종료), 모드 다시 불러오기(자식 종료), 앱 강제 종료(스크립트의 부모 감시, 3~4초) — 마지막 것은 **[실측]**, 실제 앱의 프로세스 구조는 **[미검증]**(R-05).
- 재연결은 5번으로 제한(이전에는 무한).
- 정리용 `Stop-Process -Force`는 명령줄에 `pixel-tavern-radio`가 든 `powershell.exe`만 대상입니다. 다른 프로세스가 같은 글자를 명령줄에 넣으면 같이 꺼질 수 있습니다(R-12, 낮음).

**git를 믿을 수 없는 저장소에서 부를 때 [확인]** 저장소 설정(`.git/config`)의 `core.fsmonitor`는 `git status`를 부를 때 임의의 명령을 실행할 수 있습니다. 모든 git 읽기에 `-c core.fsmonitor=false`를 붙여 막았습니다. `--no-optional-locks`는 상태 조회가 index를 갱신하며 잠그는 것을 막아, 사용자가 동시에 하는 `add/commit`이 `index.lock` 오류로 실패하는 일을 줄입니다. [시험] 모든 git 호출의 앞 4개 인자 확인. `status`와 `log`가 다른 저장소 설정(예: diff 드라이버)을 실행하지 않는다는 점은 알려진 동작에 근거한 것으로, 직접 실험하지는 않았습니다 **[미검증]**.

**비밀 정보 [확인]** 코드·도구·시험에서 `token|secret|password|api key|Authorization|Bearer`를 검색했습니다. 걸린 것은 컨텍스트 "토큰 수"(`tokens`) 표시뿐이고 키·비밀번호는 없습니다. 환경변수는 `TAVERN_URL`, `TAVERN_VOLUME` 두 개뿐입니다. 로그(`$.ui.log`)에는 오류 글만 남깁니다.

**외부 HTTP 스트림 [확인]** 방송 4곳이 모두 `http://`(암호화 없음)입니다. `https`는 이 재생 방식에서 연결에 실패했습니다(이전 실험). 위험: 같은 네트워크의 제3자가 소리를 바꿔치거나, 방송국이 접속 IP를 알 수 있습니다. 코드 실행 경로는 아닙니다(MediaPlayer가 오디오를 디코딩). 연결은 사용자가 ▶를 누를 때만 일어납니다. 오디오 디코더 자체의 취약점은 이 모드의 범위 밖입니다.

**오류 처리 [확인]** 오류를 삼키는 곳은 의도된 두 곳뿐입니다: git이 없거나 저장소가 아닐 때(`.catch(() => null)`, 정상 상태), `where.exe`가 없을 때(음악 버튼을 숨김, 정상 상태). 나머지는 토스트(`/명령 를 실행하지 못했어요`, `음악 연결 실패`)나 로그(`logFailure`)로 알립니다.

**중복 코드 [확인]** 재시도 한도는 `MAX_TRIES` 한 곳에서 정해 스크립트와 안내 문구가 같이 씁니다. 제어 문자 제거는 `trackFile` 한 곳입니다. 시험의 공용 준비물은 `tests/kit.tsx`에 모여 있습니다.

**타입 안전 [미검증]** 타입 정의(`types/index.d.ts`)와 `tsconfig.json`은 있으나, 이 환경에 `tsc`가 없어 검사를 돌리지 못했습니다. 대신 `claude plugin validate`(상태 키가 계약과 맞는지)와 자동 시험 74개로 갈음했습니다.

**모듈 의존 [확인]** `register → (actions, alerts, banner, panel, radio …)`, `panel → (layout, music, usage, diag …)`, `state → (git, scenes, format, volume)`, `radio → (state, scenes, volume)`. 실행 시점 순환은 없습니다. 타입만 서로 가리키는 곳이 둘 있습니다(`layout`·`music` → `panel`의 `PanelData`, `panel` → `banner`의 `BannerData`). 바깥 세계(git·재생기)는 각각 `git.ts`, `radio.ts` 한 파일에 모여 있습니다.

**OS 호환 [시험]** 음악만 Windows 전용입니다. `where.exe powershell.exe`로 확인해 없으면 음악 버튼이 사라집니다. 나머지(배너·패널·git·사용량)는 OS와 무관합니다. 다른 OS는 [미검증].
